## v1.x（C++ 移植版）

### agent 模式（`--agent`）

- **REPL 历史按字节预算自动裁剪**：会话历史按估重计量（正文 + 工具调用参数 + base64 图片 + extras 串，即线上体积的下界），超过 `AgentOptions::maxHistoryBytes`（缺省 4 MiB，0 = 关）在下一轮任务开始前按「任务块」（一条任务消息到下一条之前的全部消息）整块裁掉最老的块。整块裁剪保证 assistant.tool_calls 与其 tool 消息、夹在 tool 消息之后的图片 user 消息不被拆散（半截序列会被服务端 400 拒绝）；老块连同其中的 base64 图片一并释放——图片是历史体积主项，按条数裁剪挡不住；system 提示词与最新一个任务无条件保留（正在进行的对话不能裁空）。单测：字节预算裁剪 / 图片随块淘汰 / 预算 0 不裁剪
- **新增 agent 模式**：`--agent` 让大模型工具循环成为主执行流程——结构脚本加载后硬件**常驻内存**，多轮挑选并执行动作脚本，会话结束才 `deactivate()`；与管道模式互斥（与 `--tcp`/`--input` 同给退出 2）。`--task` 一次性任务，缺省交互 REPL（`/hardware`、`/scripts`、`/exit`，历史跨轮保留）
- **工具集**：`list_action_scripts`、`run_action_script`（路径限定 `--scripts-dir` 之下，拒绝绝对路径/`..`/非 `.mt`，8 MiB 上限）、`list_hardware`（只读清单，不调 `read()`/`play()`，不误触发执行器）、`capture_image`（见下）、`run_command`（超时整进程组终止 + 64KB 截断 + 环境变量清洗，`--agent-no-shell` 可关闭）。工具报错折成文本回传模型，不打断会话
- **模型调用是一颗 Lua 协议驱动**（替换最初基于 libus_http 的 C++ 实现，`src/agenthttp.*` 已删除）：与舵机、传感器平级的 `modules/*.lua` 驱动，宿主经 `src/agentdriver.*` 适配成 `ChatTransport`——恢复零链接期依赖（仅 LuaJIT + pthread + dl；运行期需 libcurl，经 ffi 加载），换模型/换厂商 = 换一个 Lua 文件。配套：宿主侧 `src/agentproto.*`（规范化消息/工具 ⇄ Json）、`src/agentloop.*`（缺 `tool_call_id` 自动合成、轮次上限/传输失败回滚本轮消息、`extras` 逐轮透传）、`src/jsonparse.*`（严格 JSON，深度 64/8 MiB 上限）；Lua 侧 `lib/json.lua`、`lib/llm_http.lua`（ffi 直驱 libcurl；整型选项必须 cast 成定签名再调，裸变参被静默忽略——实测超时失效）、`lib/llm_wire_openai.lua` / `lib/llm_wire_deepseek.lua`
- **llm_http 写回调即用即释**：每请求 cast 的回调 cdata 在 perform/getinfo 完成后 `cb:free()`——LuaJIT 回调槽位要等 cdata 被 GC 才归还，长驻会话高频请求会持续累积（2026-09-19 审计）
- **LLM 超时钳制**：`lib/llm_http.clamp_timeout` 把 `timeout`/`connect_timeout` 单点钳到 **[1, 600] 秒**——libcurl 语义下 `CURLOPT_TIMEOUT=0` 是**不限时**、负值同样透传，一个配置项就能让单次调用永远挂着；`--llm-timeout` 与配置 `timeout` 的上限同步收到 600，宿主接受什么驱动就发什么，不做「先接受再悄悄改写」（2026-09-19 评估 P1-3）
- **两个内置协议驱动**：`LlmOpenAI`（缺省）与 `LlmDeepSeek`，`--llm-driver` 切换，结构脚本未声明时宿主自动注入。后者承担三处实质差异：思考模式开关、**带 `tools` 时必须回传历史 `reasoning_content`（否则 API 400）**、思考模式不支持 `temperature` 且 `top_p` 下限抬到 0.95。API key 由驱动自己读环境变量，宿主只校验其存在，不进参数表/调试转储
- **配置文件（`--llm-config`）**：URL/API key/模型/采样与 agent 参数收进一份 JSON（`src/llmconfig.*`）。优先级**命令行 > 环境变量 > 配置文件 > 驱动缺省**；查找顺序 `--llm-config` → `BOT4CJ_LLM_CONFIG` → `./mybot.llm.json` → `./mybot.llm.conf.json` → `$HOME/.config/mybot/llm.json`，会话开始如实打印用了哪一份。严格校验：非法 JSON / 类型范围不符 / 未知字段一律退出 2；空串按未配置；密钥可写 `api_key` 或 `api_key_file`（对同组/其他用户可读时打印 `chmod 600` 提醒）；`--llm-config none` / `BOT4CJ_LLM_CONFIG=none` 显式关闭（缺省查找依赖 CWD，会悄悄改变守门结果）。选 JSON 不选 Lua：配置是数据不是代码，不让一份常被复制分发的文件获得任意代码执行能力
- **空数组哨兵**：Lua `{}` 分不清空数组与空对象，工具 schema 的 `required` 被编成 `{}` 会被 DeepSeek 严格校验直接 400——`lib/json.lua` 增显式哨兵 `json.empty_array`，驱动在 schema 语义已知处规范化；假模型服务同步校验工具 schema，此类问题离线守门即可暴露
- **摄像头工具 `capture_image`**：摄像头同为一颗 Lua 驱动 `modules/Camera.lua`（V4L2 mmap + 硬件编码 MJPEG，宿主不链采集/编码库；V4L2 ABI 构建期由 `test/test_v4l2_consts.c` 自检）。build 不碰设备（没接摄像头也要能上电），首次拍照惰性打开、失败如实报给模型、热插拔失败即释放下次重开、首帧丢弃；仅支持 MJPEG。图片不塞工具结果（tool 消息只允许文本），而是本轮 tool 消息回传完后另起带 `image_url` 的 `user` 消息注入，随历史保留；`--camera-src <图片>` 仿真让无摄像头开发机回归全链路。**路径白名单**（2026-09-19 评估 P1-2）：设备只放行 `/dev/videoN`，仿真图片只读 `--camera-src` 所在目录（或 `BOT4CJ_CAMERA_SRC_DIR` 列出的目录）之内的文件、判定走 `realpath`（软链展开后越界即拒）、两者都没给则仿真默认禁用——否则驱动经 `ffi.C.fopen` 就等价于一个「读任意路径」的原语，事实绕过沙箱对 `io.open` 的封禁
- **MJPEG 帧完整性重取**：UVC 设备可能吐出熵编码中途截断的帧（2026-09-19 实测某设备约半数帧如此；内核不置 `V4L2_BUF_FLAG_ERROR`，V4L2 层无从感知，宽松解码器 libjpeg/ffmpeg 照常出图），送 OpenAI 兼容网关会被严格解析器 400「图片输入格式/解析错误」，而补 EOI/补填充位救不回缺掉的 MCU 数据。`lib/mjpeg_frame.lua` 以「帧尾 EOI」为判据做规范化（只在帧尾窗口搜索，防 APP1 内嵌缩略图的 EOI 误判，顺带截掉 EOI 后的填充字节），`Camera.lua` 对截断帧整帧丢弃重取（上限 8 帧，失败如实报错）；真机回归断言「出去的帧必以 EOI 结尾」
- **守门**：agent 端到端扩为五场景——默认驱动完整工具循环（抓报文断言 OpenAI 形态）、`LlmDeepSeek` 协议差异断言（thinking / 不发 temperature / `reasoning_content` 回传）、`--llm-timeout` 4s 内生效（防 curl 变参 cast 退化）、`--llm-config` 断言 URL/KEY/MODEL 全部来自文件且环境无密钥、`capture_image` 断言线上报文带 data URL 包的真 JPEG；缺 python3 或 libcurl 按 SKIP 计入未执行清单。新增纯 Lua 用例 `test_json_lua`/`test_llm_drivers` 与 C++ 用例 `test_agentdriver`（假 Lua 驱动，不联网）、`test_llmconfig`；ASan 抑制 libcurl→libcrypto 的进程级初始化残留（仓库根 `asan.supp` 经 `LSAN_OPTIONS` 加载——ASan 抑制解析器不认 `leak:`，不能放 `ASAN_OPTIONS`）

### 语言与 DSL

- **controller/trigger 多列（扇出）**：放行编号列 `controller2`/`trigger2`…（基名或基名+纯数字，`controller2x` 仍是普通元数据列），一行可声明多个转发目标/触发器，执行顺序 = 列声明序。controller 扇出广播：payload「元数据 ∪ 自己返回表」只构建一次、每个 controller 收到同一份（同列族不接力，跨变量链由目标自己的 controller 列表达），**出现一个 ERR 即停止并返回**（后续 controller 不再转发、整帧 halt），全部成功返回最后一个 controller 的结果（单列与既有行为一致）；trigger 按序前置调用、结果各自按名到位。同列族重复指向、`@Alias`/`@Vars` 标量目标（controller 侧为新增装配期校验）装配期拒绝。`MetaProvider` 保留列跳过改为名字模式匹配（漏匹配会让编号列泄漏进元数据）。守门 `ctrl2_basic`/`trig2_basic`（正值 + 观察面专段）与 `flow_dup`/`flow_dupc`/`flow_fwd2`/`flow_scalar2`/`trig_scalar2`/`ctrl2_err`（负值，fail-fast 用 relay 目击者禁言断言）
- **`trigger` 前置调用列**：controller 的镜像入边——当前零件被派发前，框架先以空参数调用 `trigger` 列指向的硬件变量（一次语义完整的 play，其自身 controller 链照走），返回表经 `ensureOk` 契约检查后以**触发器名字为键的子表**并入调用参数（`data.<触发器名> = {…}`），再运行当前零件自己的 `call`。与 controller 共用「先声明」约束（引用图按构造无环，派发期免环检测）、N-6 会话别名覆盖拒绝；目标可为 Lua 驱动或守护变量（守护无首帧 `count=0` 不是错误），`@Alias`/`@Vars` 标量拒绝；只挂 play 路径（含 controller 转发嵌套与 agent `playQuiet`），`read`/`build`/`destroy` 不触发；触发器名与本表元数据列同名/框架保留键装配期拒绝、`.mt` 参数键占用派发期拒绝；controller 转发 payload 不含触发器子表（输入侧数据要继续转发须由驱动显式回显）。守门 `trig_basic`（正值 + 顺序/数据到位观察面专段）与 `trig_forward`/`trig_scalar`/`trig_reserved`/`trig_collide`/`trig_dollar`/`trig_param`/`trig_n6`/`trig_err`（负值）；`MetaProvider` 的结构引用列改按保留列名跳过（`name`/`controller`/`trigger`）
- **`$(...)` 算术表达式**：`@Vars.value`、结构脚本元数据列、`@Action` 单元格三处可用（`+ - * / %`、括号、一元正负，标识符仅限 `@Vars`）。独立递归下降解析器（`src/expr.*`）：语法错误带位置、括号深度/运算符数双上限、除零报错、出口 `isfinite` 拒绝 inf/nan；AST 惰性求值（前向引用、成环检测）。守门 `expr_num`/`expr_undefined`，单测 `test_expr`
- **`@Vars` 命名数值变量**：与 `@Alias` 同构（列 `name`/`value`），仅数值字面量或 `$(...)`，非数值注册期即报错。两种消费：结构脚本元数据列 `$<name>`（唯一允许 `$` 指向标量的类型）、动作脚本参数位替换；`.mt` 内联不得覆盖结构定义。守门 `vars_num` 正值 + `vars_bad`/`vars_nonnum`/`vars_dup`/`vars_override` 负值
- **结构脚本 `Number` 列类型**：解析期一次数值校验（拒绝空值/`nan`/`inf`），值仍按文本驻留。守门 `number_type`/`number_bad`
- **词法器**：引号内 `--`、`/* */`、`;`、`,` 一律按字面数据（`sqlquote` 回归）；引号态增量维护，消除逐字符重扫 token 的 O(n²)；`.sql` 与 `.mt` 统一 8 MiB 上限（`LimitedReader`，报错区分输入类别）
- **mtmerge 归并 `@Alias`/`@Vars`**：多 .mt 合成时按行叠加，两侧列头须一致，同名行报错退出 2；守门含正值归并、同名负值与产物回喂端到端

### 执行引擎与安全

- **守护错误退避可被 stop 打断**：C-L2 退避上限 ×256（interval 上限 1h → 单次退避睡眠可达数天），一次性 `sleep_for` 会吞掉停止请求——stop 落在一次超过 join 超时（保底 2000ms）的深睡中段时必然走弃管路径，`requestStop`/`waitForExit` 的停止语义被架空（弃管兜底仍在，但「join 等它退出」失效）。退避睡眠改为 100ms 分段逐片睡、每片醒来查 `daemon_stop_requested`：退避总时长不变，stop 响应延迟收敛到单片时长。回归测试按窗口推演构造（在第 8 错的 2560ms 深睡中段请求 stop：旧行为必弃管、新行为 ≈30 倍余量内 join），并双向验证（临时禁用 stop 检查 → 测试 FAIL）。单测总数 263 → 267
- **沙箱残余缺口如实声明**：`luaend.hpp` 的 `sandbox_lua` 注释列明三项有意取舍——`load`/`loadstring` 未包裹（字符串源码不受路径白名单约束）、`luaL_loadfile` 接受 LuaJIT 预编译字节码（白名单只限路径，不区分源码/字节码，字节码加载器是经典 LuaJIT 攻击面）、`ffi` 本身即完整逃逸通道——依据 docs/reference.md 的威胁模型（modules/ 下 .lua 信任级等同 mybot 用户，沙箱防误用与路径穿越、不对抗恶意驱动代码），此前头文件未把前两项列为已声明残余
- **异常体系与文案惯例收口**：`agentdriver` 两处 `std::invalid_argument`（`logic_error` 谱系）归口 `IllegalArgumentException`（`runtime_error` 谱系，util.hpp 单一根），与「统一按 IAE 收口」纪律一致；`docs/development.md` 声明报错文案分语言惯例（结构脚本装配/解析期英文面向脚本作者，agent 与运行期中文面向操作者），并要求不新增散装异常类型
- **`$` 引用校验前移**：存在性校验从惰性提前到全部表装配完成后、任何驱动 `build` 之前——失败不碰真机；前向引用仍合法。守门 `ref_forward`/`ref_undefined`；`$` 指向标量清晰报错而非 Json 类型崩溃（`ref_alias_scalar`）
- **destroy 元数据恢复引用列**：改为「字面列 + 引用列尽力而为快照」——引用仍存活则并入快照，已释放只跳过该引用、`destroy` 本身绝不跳过；修复 `fd` 缺失导致 PCA9685/MPU6050 响亮报错、十余款器件静默丢失去初始化的问题
- **并发与退出路径收口**：守护槽指针改 `std::atomic`、守护退出 `count` 移入槽内 mutex 临界区、弃管以「退出检查点 + 原子 exchange 唯一胜者」裁决消除泄漏竞态；守门新增信号/退出路径段（播放中与 TCP 等待中 SIGTERM 两分支）
- **TCP 动作源加固**：非回环监听强制口令 + 恒时比较 + 先取脚本后上电；凭据行超长 fail-closed 拒绝；裸 `--tcp` 不再静默回落端口 1；口令失败关连接回 accept 等待、连续 5 次才退出（防单次连接 DoS 与无限爆破）；新增连接总时长预算（600s，随 `--tcp-idle` ×20 放大）堵慢滴击穿空闲超时；口令可经环境变量 `BOT4CJ_TCP_TOKEN` 传递。`tcp_adversarial.sh` 扩为七场景
- **动作派发热路径优化**：`@Action` 列头只解析一次、`$(...)` 表达式 AST 按列缓存、`Json::getPtr` 就地更新子字段（消除逐拍派发的双深拷贝）、`findMt` 改返回指针
- **沙箱与加载防线**：`call_lua` 拒绝含 NUL 的键/值（堵 reserved-key 截断绕过）；dofile/loadfile 白名单按分量精确匹配、容忍尾斜杠；未知/拼错 `--key` 报错退出 2（不再打印帮助假成功）；MS5611 非法 `osr` build 期显式 ERR 且先于总线动作
- **浮点窄化值域防线**（2026-09-19 评估 P1-1/P1-5）：`agenttools.optionalInt`（模型可控的 `timeout_seconds`）与 `llmconfig.wantInt`（配置文件数值）在做 `static_cast<int>`/`static_cast<long long>` 之前先判有限性与值域——`1e30`/`1e300` 这类值直接转换是 float-cast-overflow UB（UBSan 实证），现一律在转换前响亮拒绝（与 `luabridge.cpp` 的 int64 键/值路径同一族判据）
- **工具脚本路径沙箱硬化：拒绝符号链接**（2026-09-19 审计中危 #5）：`readFileLimited` 改用 `open(O_RDONLY|O_NOFOLLOW|O_CLOEXEC)` + read 循环（不做 lstat 后再 open 的 check-then-use），`scripts/` 里的软链不再能把目录外文件当动作脚本执行；`describeActionScripts` 修两处——软链条目一律不收（原先 `fs::relative` 内部会 weakly_canonical，把软链解析成带 `..` 的越界路径，**目录外文件的首注释会经清单回显进模型上下文**）、相对路径改 `lexically_relative` 纯词法求（尾斜杠不影响前缀匹配）。守门 `agenttools_run_action_script_rejects_symlink`（正常脚本不受影响 / 软链被拒且不泄露内容 / 清单不列软链 / 尾斜杠目录照常列出）
- **API key 对 agent 的 shell 可见性告警**（2026-09-19）：环境变量清洗只覆盖「环境变量」这一来源——`run_command` 的子进程与宿主**同属一个用户**，密钥若来自配置文件 `api_key`、密钥文件 `api_key_file` 或 `--llm-key`，脚本一句 `cat` / 读 `/proc/<pid>/cmdline` 就能拿走（`chmod 600` 这类权限位对同用户无效，此前文档把「配置文件」当作规避 `/proc` 暴露的手段，属误导）。`AgentModeConfig` 新增 `apiKeySource` 记录来源，`shellKeyExposureWarning` 在 `run_command` 启用且命中上述来源时启动告警，并给出规避路径（改用环境变量，或 `--agent-no-shell`）；提示只讲来源、**绝不复述密钥本身**；默认行为不变（`run_command` 仍默认开启）。守门 `agentconfig_key_source_is_recorded_and_flagged`（四种来源分别核对）与 `agentconfig_shell_key_warning_is_silent_when_shell_disabled`

### 驱动与总线

- **驱动入口收敛（两刀）**：第一刀 SHT3X/BME280/BMI270 六处手搓 fd/address + set_addr 校验迁至 `drv_common.i2c_pair`；第二刀 MCP4725/TPL0501 的 build/call 校验迁至 `drv_common.arg_table`（入口第一行，代调 `virt_prepare`）——旧风格入口绕过直驱 virt 注入钩子，`proto=virt` 的 @Action 直写会绕开仿真打到真实总线（2026-09-19 审计发现 27 个旧风格驱动，本刀先迁两颗写路径 DAC），`call` 报错文案与 `arg_table` 口径统一；新增 E2E `mcp4725_virt`（第二条非守护 virt 用例）钉住该能力
- **新增 `SCSCL` 总线舵机驱动**（飞特 FT-SCS 协议，UART）：PING 探测、位置/时间/速度/扭矩、反馈块读取、`set_id` 站号烧写（须结构期 `allow_burn` 授权，负值守门 `scscl_burn_guard`）；内嵌 `SCSCL_VIRT` 协议模型，147 断言 + 2 条 E2E
- **UART 修复**：波特率必须传 glibc `B*` 常量——旧实现传数值 Hz 被 EINVAL 拒绝且未查返回码，波特率从未生效（白名单扩 500000/1000000）；open 时快照原始 termios、close 先恢复再关闭；call 下发 build 缓存的 path 而非信任 call 元数据（virt 模式按错误 tty 路径 attach 的缺口关闭）
- **virtbus 对齐与前置修复**：读族入参校验对齐 HAL（非法寄存器/地址不再取模静默回绕，超时上限对齐）；`drv_common` 改先实例化再 attach（旧实现工厂直挂导致写静默成功、读永远无应答）；新增 `BUS="uart"` 模型与跨状态机 uart fd 采纳
- **驱动 build 全程守卫**：`drv_common.guard_build` 统一 pcall——build 在打开总线句柄后抛 Lua error 时折成 ERR 契约并回滚关闭句柄（I2C/SPI/UART/GPIO 全部接入）
- **sensor_daemon 浮点防线**：浮点物理量配 `sign=16`/`:s16` 会被 floor 截断成整数假值静默发布——拒绝发布、tick 错误点名让配置改 `:f`；新增 virt E2E `float_s16_daemon`
- **样板单点化**：`bitcompat` 新增符号扩展原语 `s16/s12/s8/s16le/u16le`（置于 LuaJIT 早退分支前，双解释器共用），BME280 校准系数解析改用之；GPIO 成功打印纳入 DEBUG 门控
